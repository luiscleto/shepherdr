# Herdr integration discovery

Status: proposed discovery, not approved architecture

Base commit: `fc75b852a7bc22e26941f63fec715dfa9cf21421`

## Scope and evidence

This document maps Herdr's current integration surface. It does not choose a Shepherdr architecture, product behavior, data model, or build order.

Findings use these labels:

- **Confirmed** — stated by the installed Herdr help/schema or demonstrated by version-matched source or a bounded live check.
- **Inference** — follows from confirmed behavior but is not an explicit Herdr contract.
- **Unknown** — evidence is insufficient.
- **Not exposed** — the inspected version has no generic interface for the capability.

The primary target was the running default session on 2026-08-16: Herdr `0.8.0`, socket protocol `19`, client/server compatible, Unix socket `/home/luisc/.config/herdr/herdr.sock`. The installed Codex integration was current at v7. Evidence that another person can repeat:

All findings are version- and capability-sensitive. Herdr's protocol is versioned, agent detection manifests can update independently, integrations have their own versions, native session restore varies by agent, direct attach is Unix-only in the current Windows beta, and pane history and graphics are experimental settings. A client must check the running server protocol/capabilities rather than assume this exact surface.

## Findings

| Question | Finding | Confidence and consequence |
| --- | --- | --- |
| Workspace and agent discovery | `session.snapshot` is the bootstrap view: workspaces, tabs, panes, layouts, agents, focus, version, and protocol. `workspace.list`, `pane.list`, and `agent.list` provide narrower reads. An agent is a recognized process occupying a pane; ordinary panes exist without agents. Named Herdr sessions have separate sockets and state. | **Confirmed.** Reconnect guidance is explicitly “snapshot again, then subscribe.” IDs must be read from responses, not derived from order or labels. |
| Identity and reconnect handles | Public handles are opaque: workspace `w…`, tab `w…:t…`, pane `w…:p…`. They are persisted and restored by v0.8.0, and closed tab/pane IDs are not reused. A cross-workspace pane move assigns a new pane ID. `terminal_id` identifies the live PTY and is newly allocated on a cold restore. An optional `agent_session` is a read-only native conversation reference. Agent names are aliases for the current live occupant and clear on exit, release, or replacement. | **Confirmed implementation; contract strength partly unknown.** Workspace/tab/pane IDs are the best available reconnect handles, scoped to a Herdr session. Pane IDs are not move-proof. Terminal IDs are live-session handles, not cold-restart deep links. Agent names and native session references are not accepted as durable general deep-link identities. The docs do not explicitly guarantee public-ID preservation across every future protocol version. |
| Status words | Herdr exposes exactly `working`, `blocked`, `idle`, `done`, and `unknown` on agents and rollups. `done` is idle work not yet seen; focusing its tab/pane/agent marks it seen and returns it to `idle`. CLI reads do not mark it seen. `blocked` means an integration or screen rule recognized a question/approval UI. `unknown` means Herdr cannot classify confidently, not success or failure. | **Confirmed.** Shepherdr need not infer lifecycle state. Detection remains manifest/integration sensitive; the live Codex pane was classified by remote manifest `2026.08.09.1`. |
| Status and topology changes | Long-lived `events.subscribe` streams resource lifecycle and per-pane `pane.agent_status_changed` events. `agent.wait` is server-owned and event-driven. Subscriptions end on disconnect/restart and have no durable cursor. | **Confirmed.** Status and topology do not require client polling while subscribed, but clients must resnapshot after a gap. |
| Output changes | A terminal observer pushes live rendered frames. The ordinary socket subscription surface offers pattern-specific `pane.output_matched`, not an unfiltered all-output subscription. Its v0.8.0 implementation repeatedly reads the selected snapshot. Pane/agent reads return a `revision`; terminal frames have connection-local sequence numbers. | **Confirmed.** Live terminal rendering is event-driven. Generic “new output” across every agent otherwise needs one observer per terminal or polling/revision comparison; Herdr does not expose durable output events that can be replayed after an offline gap. |
| Sending input to an agent | `agent.prompt <target> <text>` atomically sends text and Enter to the recognized live agent, honoring bracketed-paste mode. It accepts a pane ID or unique live agent name and rejects the operation when that agent no longer occupies the pane. `agent.send_keys` handles interactive keys. Raw pane input remains available when terminal control is intentional. | **Confirmed.** This is the generic agent-level input path. It is text submission to the agent's terminal UI, not a provider API call. Multiline text is supported as one bracketed paste. |
| Structured/chat interface | The socket API is structured for runtime control, status, waits, and reads. It does not expose chat messages, roles, turn IDs, turn boundaries, delivery/read state, or a conversation transcript. Herdr explicitly says `agent.prompt --wait` does not track an individual turn. `agent.read` returns rendered terminal snapshots. | **Not exposed.** There is a structured control interface apart from keystrokes, but no generic chat-level data interface. |
| Images and attachments | `agent.prompt` accepts only text. No generic agent attachment/file/image field appears in the v0.8.0 schema. Remote desktop image paste can stage an image and paste its path during `herdr --remote`; that is a client-specific clipboard bridge. Experimental pane graphics display pixels over a pane and are not agent input. | **Confirmed absence.** Multiline text is generic; images and attachments are not. Treating a Shepherdr upload plus pasted path as an attachment would be new product/security behavior, not existing Herdr semantics. |
| Output observation and replay | `pane.read`/`agent.read` offer `visible`, `recent`, `recent-unwrapped`, and detection snapshots with a revision and truncation signal. Alternate-screen rows that leave the screen do not enter host scrollback. Reconnecting a terminal observer yields a full current rendered frame, then live deltas. Cold-restart pane history is experimental, off by default, and stores sensitive terminal output. | **Confirmed.** Herdr can replay what the live terminal still retains, not a complete chat history. After cold restart, recent screen content exists only when pane history was enabled; native agent resume restores the provider conversation but does not expose it as structured Herdr messages. |
| Real terminal attach | `herdr terminal session observe <target>` emits NDJSON `terminal.frame` records containing base64 ANSI, followed by `terminal.closed`. Multiple observers are allowed. `herdr terminal session control <target>` adds NDJSON `terminal.input`, `terminal.resize`, `terminal.scroll`, and `terminal.release`. One controller owns input and resize; `--takeover` replaces it. The server owns the PTY and process. | **Confirmed, including the bounded live check.** This is the real-terminal bridge. A bridge reconnects by resolving the current target and opening a new stream; it receives a new full frame rather than resuming by old frame sequence. |
| Chat and terminal as views of the same work | Both `agent.prompt` and terminal control target the same Herdr-owned pane/agent process, so they can share one runtime. However, terminal-derived reads are lossy and unstructured, and Herdr supplies neither complete conversation replay nor attachment semantics. | **Confirmed plus inference.** A live, best-effort text projection can be another view without a second runtime. The complete promised Chat experience is not currently supported as a truthful, reconnectable chat view unless Herdr exposes more structure. Persisting reconstructed turns in Shepherdr would create the separate conversation store the product direction forbids. |
| Notification inputs | Per-pane status subscriptions can drive blocked transitions. `done` plus `state_change_seq` can represent completed unseen work. Terminal frames or revision changes can indicate output activity, but not a message or its author. Herdr's own `notification.show` displays through its configured foreground client; it is not a durable mobile push service. | **Confirmed.** Blocked-agent notification input exists. A truthful “new message” notification and offline catch-up marker are not exposed generically. |
| Disconnects, restarts, completion, disappearance | A Shepherdr disconnect/restart does not stop Herdr; reconnect requires a fresh snapshot and subscriptions/terminal streams. A normal Herdr cold restart ends clients, waits, and streams; PTYs/processes stop, layout/public handles restore, terminal IDs change, and eligible official native sessions may resume. Experimental live handoff may preserve PTYs but still interrupts transient requests/streams. When an agent exits or is replaced, its live alias clears and agent operations can return not-running; completion while still present is `done` or `idle`. Closing a workspace emits `workspace.closed`; later lookups return not found. | **Confirmed.** A disappearing target must become honest unavailable/stale state, never be silently recreated. Events missed during any gap are recovered only through current snapshot, not replay. |

## Direct architecture implications

These are constraints that follow from the confirmed surface, not an architecture proposal:

- Herdr can remain the authority for topology, live processes, lifecycle status, input, and terminal rendering. A reconnecting consumer can bootstrap from `session.snapshot` and then follow subscriptions and terminal streams.
- Any cached Shepherdr state is necessarily a fallible projection. After disconnect, protocol change, or suspected event gap, current Herdr state must replace it.
- Deep links need a Herdr session scope plus a current resource handle and must tolerate `not_found` and pane moves. No exposed identifier is simultaneously stable across live-agent replacement, cross-workspace pane movement, cold restart, and session recreation.
- The real terminal view has a purpose-built bridge with PTY fidelity, resize, scroll, reconnect, and explicit single-controller ownership. Raw `pane.send_text` is not an equivalent terminal session.
- Herdr status can drive “blocked” truthfully. Rendered output activity cannot by itself be called a new chat message.
- Chat can submit text to the same work through `agent.prompt`, but a faithful conversation view, blocked-choice UI, image attachment, and offline history cannot be derived from the current generic surface without adding semantics outside Herdr.

## Remaining unknowns

- Whether preservation of public workspace/tab/pane IDs across cold restore will become an explicit compatibility guarantee rather than a v0.8.0 implementation fact.
- Whether named sessions are in Shepherdr's intended scope, and, if so, what stable server/session identity should scope otherwise reusable public IDs.
- How concurrent `agent.prompt` callers are ordered and what acknowledgement is sufficient when an agent is already `working`; current waits do not identify turns.
- Whether Herdr plans an unfiltered output-change subscription with a replay cursor, or structured message/blocked-input/attachment APIs.
- Whether every supported agent and integration reliably distinguishes blocked questions from approvals and supplies native resume references; this varies by integration and manifest version.
- What explicit capability query should report pane-history availability, native-resume eligibility, direct-terminal support, and other experimental/platform-sensitive features. Protocol version alone does not express all of them.

## Capabilities Herdr 0.8.0 does not expose

- A provider-neutral message/turn model with roles, stable IDs, completion boundaries, and transcript replay.
- A provider-neutral description of what a blocked agent is asking for, including choices and the accepted input shape.
- Generic image/file attachment input with staging, MIME/name metadata, progress, acknowledgement, and lifecycle cleanup.
- Durable, cursored event or output replay for offline notification catch-up and “new since last seen.”
- A durable agent/work identity that survives pane movement, agent replacement/resume, and session recreation while remaining directly targetable.
- A message-level event suitable for truthful new-message notifications.

## Recommended next architecture question

Decide one question before designing Shepherdr's Chat: **Is Chat allowed to be an explicitly live, lossy terminal-derived projection over `agent.prompt` and `agent.read`, or does the product require a Herdr-owned structured conversation, blocked-input, replay, and attachment contract first?**

The first option can share the real Herdr runtime now but cannot satisfy reliable history, message notifications, blocked choices, or generic image sending. The second preserves the product's “same work, no second conversation store” promise, but makes the missing Herdr contract a prerequisite. The evidence favors defining that minimum Herdr-owned contract before treating the complete Chat promise as architecturally available.
