## Approved history limitation

**Exact shared loaded history is not supplied by the existing Herdr interfaces.** Reader asks for up to 20,000 recent unwrapped lines in 500-line increments. These are snapshots, not replay bytes with an offset into the terminal stream. The stream supplies rendered viewport frames; xterm resets on a full frame. Herdr's `terminal.scroll` changes the authoritative viewport or sends application wheel/key input, depending on the running terminal's modes. An observer cannot use it. It is unsafe to turn Reader's older-history fetch into automatic `terminal.scroll`, and counting unwrapped Reader lines cannot establish a corresponding terminal scroll position. [Reader](../web/src/terminal/reader-view.ts), [read/stream protocol](../internal/server/terminal_protocol.go), [xterm](../web/src/terminal/xterm-adapter.ts), [Herdr scroll implementation](https://github.com/herdrdev/herdr/blob/b99002ac99b09e00b4ca692436cb15a6b0d676f1/src/server/pane_input.rs#L106).

The human approved independent history navigation for this trial: both views reach the same history still retained by Herdr, independently. Reader keeps its fetched snapshot and position; full Terminal navigates Herdr history through deliberate terminal scroll while controlling. Fetching older Reader output neither primes xterm scrollback nor moves the full terminal. Exact shared loaded history is not required for this trial.

Do not reconstruct an emulator, splice read snapshots into xterm, or replay painted frames as history. The human subsequently approved Herdr 0.9.0 as this trial's minimum (see the resumption record below). No disposable probe can turn the documented snapshot interface into replay. Further broad research is unnecessary.

## Implement the trial

**Views and ownership.** Mobile opens Reader. Add a 44-pixel accessible **Full terminal** / **Reader** toggle in the top-right beside Settings. Mount the existing `XTermAdapter` and `ReaderView` once for the exact target. Switch presentation, not TerminalPage or target. Preserve Reader nodes, loaded depth, scroll, text selection range, composer draft/caret/open state, pending files, and preview URLs. Suspend hidden Reader painting/history fetching; remember that live output arrived. Resume using its existing selection/away-from-bottom protections. Do not run `connectionReset`, `open`, or a forced Reader render merely because of a toggle. Never restore a stale selection over a selection the person subsequently changed.

Use one active mobile `TerminalSession`, shared by both views. A control stream already supplies frames, so remove the concurrent mobile observer when controlling. Feed validated full/delta frames to the mounted xterm even while Reader is visible; use arrivals only to schedule Reader's existing read. Preserve the desktop renderer and desktop interaction contract. [Current page lifecycle](../web/src/terminal-page.ts), [session](../web/src/terminal/session.ts), [ownership](../web/src/terminal/ownership.ts).

| Event | Required behavior |
| --- | --- |
| Open exact target | Measure first; try ordinary control once, without input or focus. Retain it while Reader is visible. If occupied, attach as observer and offer confirmed takeover. |
| Toggle / Message / successful send | Keep the connection and control. Message opens the existing composer. Never acquire/release per send. |
| Explicit Control / confirmed Take over | End the observer, attach ordinary control or explicitly confirmed takeover. No buffered typing is released on acquisition. Reader conflict recovery may submit only the one action explicitly confirmed as **Take over and send**. |
| Release | End control, attach observer; preserve both views. Disable automatic reacquisition for this visit until explicit Control. |
| Another controller takes over | Become observer; do not fight back. Any handed-off but unconfirmed input becomes unknown. |
| Connection loss | Keep local reading/draft/file state; disable remote input. Reconnect the same exact target using the existing delay and liveness rules. If control was desired, attempt ordinary control once; conflict leaves observation. Never repeat takeover or input automatically. |
| Home, target replacement, unmount, access cancellation | Abort pending upload work, release/close the owned stream, stop its retry timer, dispose views only on unmount. Never resolve another terminal as fallback. |

Keep necessary **Control**, **Take over**, **Release** recovery/release actions compact within the existing terminal actions in both mobile views, showing only the applicable action. Do not add a persistent ownership button row to mobile Reader or extra controls beyond necessary explicit ownership recovery/release. Preserve the compact UI and the current “The current controller will lose input” confirmation warning. Mode switching itself performs **zero** attach, release, or reconnect operations. Ownership transitions necessarily open another stream: Herdr accepts observe/control only on a pending connection, and release detaches. “One connection” means one active terminal stream, not an impossible in-place ownership upgrade. Reader reads and upload HTTP requests remain separate. [Herdr attach/resize](https://github.com/herdrdev/herdr/blob/b99002ac99b09e00b4ca692436cb15a6b0d676f1/src/server/headless.rs#L1328), [CLI lifecycle](https://github.com/herdrdev/herdr/blob/b99002ac99b09e00b4ca692436cb15a6b0d676f1/src/client/terminal_sessions.rs#L24).

Log measured pixels, fitted cells, transmitted dimensions and received dimensions in test evidence. A view toggle at an unchanged content rectangle must produce no resize. Composer/keyboard geometry can legitimately change rows. Remove the Reader temporary resize workaround and its forced refresh coupling. No whitespace padding tricks.

Full Terminal uses xterm's real textarea/input path, focused by an explicit tap; Reader acquisition and background reconnect must not summon the keyboard. Route deliberate full-terminal touch scroll through the existing bounded `terminal.scroll` contract while controlling; do not mistake xterm's local scrollback for Herdr history or emit a second scroll through xterm's default handler. Therefore mobile IME and application behavior are **unverified gates**, not source-proven parity with native Herdr. Do not add a second keyboard encoder or provider handling to conceal a failure.

**Files and input.** Keep Reader's current composer, Photos/Files choices, preparation, removal, previews, file-only and text-plus-files Send behavior. Keep recognized-agent gating and exact workspace/pane/terminal revalidation in both views; arbitrary means file type, not broader upload authority. Keep the Reader text draft separate from this action. Full-terminal insertion carries `[User uploaded /absolute/path] ` per validated path in one complete bracketed-paste chunk: single-line content, no CR/LF, no trailing Enter, and no call to `terminalSubmission`. Reader Send retains its existing path-list convention and one final Enter. Insert at the remote application's current cursor, not by editing rendered DOM or the Reader draft. While committing an insertion, reject duplicate actions and other local input until its result; do not queue that input.

File transport stays base64 JSON over `/api/terminal/files`, with current limits, ownership markers, workspace gate, rollback and cleanup. Its current `SendBatch` opens another controller and would conflict with retained control. **Trial server wiring:** register a short-lived opaque handle for each live controlling bridge connection and return it to that connection. An upload supplies that handle and an explicit insert-versus-submit intent. Resolve it only to that same exact target and current controlling connection; in protected mode also require the same existing `SessionIdentity`. The handle conveys no sign-in authority. In sign-in-off mode preserve existing operator and Host/Origin boundaries; do not invent device ownership.

Keep `StageAndForward` holding the workspace gate through validation and forwarding. Its callback writes the server-generated batch to the resolved existing child stdin through `forwardTerminalBatch`. Serialize complete batches with normal stream commands and release, without holding the write lock during file reading/staging or blocking heartbeat/frame output. Check both request lifetimes, current authority, target lease and staged directory immediately before writing. Unregister on close; never follow the handle onto a replacement connection. Do not nest the same access authority lock. This is a live connection lookup, not a staged-file token store, second runtime, replay queue or new upload endpoint. Independent review must verify this security-sensitive wiring. [Upload handler](../internal/server/file_uploads.go), [batch writer](../internal/server/terminal_batch.go), [manager](../internal/uploads/manager.go), [existing access helpers](../internal/server/access_boundary.go).

Keep existing HTTP requests without the new fields compatible with their existing batch behavior; the new mobile UI always supplies the retained-connection handle. This isolated trial requires Herdr 0.9.0 or later; 0.9.0 remains the supported maximum, with the existing honest best-effort warning for newer or unknown versions. Preserve upload `50MiB`/`none` semantics and stream limits. Do not put file bytes on the 1 MiB terminal-command socket or release control around an HTTP send.

One user action has one completion source: stream request-ID acknowledgement for text/shortcuts, HTTP outcome for files. The file callback must not also trigger a browser paste/send. Preserve existing definite-before-write versus unknown-after-possible-write classification, bounded bridge buffering, draft retention and deliberate recovery. Acknowledgement means the bridge forwarded input, not PTY consumption or agent receipt. Unknown retains staged files and never triggers automatic re-upload, reinsert or Enter. User retry can duplicate input; retain the existing check-before-retrying message.
